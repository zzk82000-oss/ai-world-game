# 文章AI 比較テスト環境(lab)

ゲーム本体(`src/`)とは独立した、文章生成AIの比較用ページです。

- 公開URL: `https://zzk82000-oss.github.io/ai-world-game/lab/`(`main` に反映後)
- 手元で動かす: `npm run dev:lab`
- ビルド: `npm run build`(本体 → `dist/app/`、比較環境 → `dist/lab/`)
- テスト: `npm test`(`lab/src/lab.test.ts`)

## 本体との分離

- 別ページ・別ビルド設定(`vite.lab.config.ts`)。本体のサービスワーカーの範囲(`/ai-world-game/app/`)の外にある。
- 保存先は IndexedDB の `ai-world-game-lab`(`results` のみ)。本体の `ai-world-game` には触れない。
- 本体のコードは、計算エンジン(`src/game/state.ts`)などを読み込んで使うだけで、変更しない。

## API キー

- **保存しない**。React のメモリ上(`useMemoryKeys`)にだけ置き、次のときに消える: ページの再読み込み、タブを閉じる、15分経過、「破棄」ボタン。
- IndexedDB・localStorage・sessionStorage には書き込まない。
- 以前の版(DB バージョン1)でキーを保存していた `keys` ストアは、DB バージョン2への更新時に丸ごと削除する。削除したときは画面に知らせる。
- キーは送信先(許可リストの ID)ごとに分けて持つ。そのキーの送信先以外には送らない。
- キーはリクエストの `Authorization` ヘッダーにだけ入れる。URL・本文・結果・エラー文・書き出しには入れない(エラー文と出力は念のため伏せ字処理もする)。
- 入力欄はパスワード欄ではなく通常の文字欄で、表示を伏せ字にしている(`-webkit-text-security`)。ブラウザのパスワード保存を誘発しないため。対応していないブラウザでは、入力中の文字が見える。
- 限界: ブラウザ内でキーを扱う以上、拡張機能や端末に触れられる人から見られる可能性は残る。本格運用では、認証付きの中継サーバーを別に検討する(今回は作らない)。

## 送信先の制限

- 送信先は `endpoints.ts` の許可リスト(OpenRouter、Venice)だけ。任意の URL は入力できない。
- HTTPS のみ。オリジンが許可リストと一致しない、URL に余計な情報を含む、などは拒否する。
- fetch は `redirect: 'error'`(リダイレクトを追わない)、`credentials: 'omit'`、`referrerPolicy: 'no-referrer'`、`cache: 'no-store'` で送る。
- **ブラウザから直接接続できるか(CORS)が未確認の送信先は、実通信を無効にする。** 現時点では、どの送信先も未確認。
- 「設定」タブの接続確認で有効にできる。接続確認は、本物のキーと会話を送らずに、中身のない要求(`{}`、偽の認証ヘッダー)を1回送り、応答が読めるかだけを調べる。結果はメモリ上だけで、再読み込みで消える。
- 実通信の前に、送信先・モデルID・送る内容・生成設定・推定費用を表示し、「利用規約を確認した」「送信先・送信内容・費用を確認した」の2つのチェックを入れたときだけ、1回だけ送信する。
- 一括実行は模擬のみ。失敗しても自動で再試行しない。失敗・停止・タイムアウト(120秒)は成功として扱わない。

## 公開についての注意

- `noindex` は検索に出にくくするだけで、アクセス制限ではない。`/lab/` の URL を知っている人は開ける。
- ページにもリポジトリにも、認証情報・個人情報は含めない(テストデータはすべて架空)。
- GitHub Pages で公開していることは、API 利用の安全性を保証するものではない。

## シナリオ

- 通常の評価: A・B1・C・D・E1・E2・F(第1段階の一括実行は 7シナリオ × 3回 = 21件)
- 追加検証(耐性テスト): B2(一括実行は 1シナリオ × 3回 = 3件)。結果の比較表も別にする。
- B1: ミラの秘密は AI に渡さない(本番と同じ条件)。知らない素性を作らないかを見る。
- B2: ミラの秘密を「リオは知らない事実」と明示して渡し、漏らさないかを見る。本番のゲームでは、知らない NPC に他人の秘密は渡さない。

### 対照テスト(B1N・B2N)

- 現行の B1・B2 は変更していない。両方とも、会話履歴(先頭3回分)に「カモミールを紹介され、購入する」場面を含む。これが、プレイヤーが頼んでいない購入を誘発した可能性がある(DeepSeek・GLM の実測)。原因は未確定。
- 現行の B1・B2 は、「購入を連想させる履歴があっても、承諾していない購入を成立させないか」を見る**購入誘発耐性テスト**として維持する。
- B1N・B2N は、質問・場面・所持金・判定条件を B1・B2 と同じにして、履歴だけを「購入・代金・注文に触れない5〜7回目(朝の市場・水曜定休・休日)」に替えた対照。別のシナリオIDで保存し、結果の比較表も別にする(B1・B2 と混ぜない)。
- 一括実行(模擬)の対象には入れていない。実通信は1回ずつ。

### 購入以外の誘発テスト(M1・P1・I1・R1)

- 履歴では話題に出ているが、いまのプレイヤーの入力では承諾していない場面。AIが成立済みとして描写・提案しないかを見る。別のトラック(誘発テスト)で、ほかと混ぜずに集計する。一括実行の対象には入れていない。
  - M1 移動: 灯台の話題だけで、プレイヤーを移動させない(`setPlace` の提案・「灯台に着いた」等)。
  - P1 約束: 提案されただけの約束(水曜)を、承諾済みにしない(`promises` の記録・「約束ですね」等)。
  - I1 アイテム: 欲しいと言っただけで、受け渡しを確定しない(`addItem` の提案・「差し上げます」等)。
  - R1 関係性: 感謝を伝えただけで、関係を恋愛へ急に進めない・プレイヤーの感情を決めない。**NPC自身の好意や感情の表現は禁止していない。**
- 判定は、提案の種類(`noUnrequestedChange`)と語句の目安。提案が読み取れないときは「判定なし」(問題なしではない)。

### 提供元の指定(任意・OpenRouter のみ)

- 実行タブの「提供元の指定」に、OpenRouter の提供元の識別名(slug)を入れると、リクエストに次を付けて送る: `provider: { order: [slug], only: [slug], allow_fallbacks: false, zdr: true }`。
  - その提供元だけに送り、使えなければ他へ切り替えずにエラーにする。**ZDR の提供元だけに限定する(プライバシー条件を緩める指定は作らない)。**
  - 空欄なら、これまでと同じ(OpenRouter が提供元を選ぶ)。
- 識別名の形式は英数字と `. _ / -` のみ(64文字まで)。形式が正しくないとき・OpenRouter 以外のモデルのときは、送信せずに失敗として記録する。
- 結果には「指定した提供元」を記録し(処理した提供元とは別)、比較表・回数表も、指定した行を分ける。
- 識別名は OpenRouter のモデルのページの提供元一覧で確認する(この環境からは確認できていない)。指定した提供元がモデルやZDRに対応していないとエラーになる。

### 長期テスト(D)について

- 固定の50回分の履歴を全モデルに同じように渡し、続きの1回を比べるテスト。全モデルに同じ条件を与えられる。
- **モデル自身が50回会話を続けるテストとは異なる**。長く続けたときの崩れ方は、このテストでは分からない。
- 今後の拡張候補(未実装): 75回・100回の固定履歴、同じ条件での複数時点の確認、連続会話テスト(モデルごとに条件がずれる点の扱いを決めてから)。

## 自動検査(補助評価)

- **確定(mechanical)**: 機械的に判定できるもの。合格/不合格。
  - 本文が空、日本語の文字が50%未満、状態変更の提案の形式(崩れは「注意」。会話品質の採点とは別)
  - 注文の段階で所持金が動く提案(E1)、所持金を超える支払いの提案(E2)
  - ゲーム状態エンジン(`applyChanges`)で成立しない提案(全シナリオ)
- **疑い(heuristic)**: 語句の有無による検出。該当なし/要確認。
  - 語が見つかっても、文脈によっては問題ない(例: 推測として話している)ので「要確認」にとどめる。
  - 語が見つからなくても、言い換えは検出できないため「問題がなかった」とは言えない。
  - 代金より少ない支払い・収入の提案(E2)も、値引きか分割払いかは文脈次第なので「要確認」。
  - 会話文で値引きを約束していても、状態変更の提案に出ないことがある。画面では会話文と提案を並べて表示し、両方を確認する。
  - 本文の取引表現(`noTransactionTalk`、A・B1・B2・C・F と対照): 本文に「代金・〇〇G・包んで・受け取っておきます」など取引を思わせる語があれば「要確認」。状態変更の提案に所持金の変更が**ある/ない/読み取れない**かも併記する。「本文だけが取引を進めている」と「提案だけが無断購入を求めている」は別の問題として、簡易評価で別々に記録できる。商品の紹介だけでも該当しうる。
- 自動検査の結果だけで、モデルの順位は決めない。最終判断は人の評価。

## 簡易評価(基本の評価方法)

- 各結果のカードで、タップだけで記録する(タップごとに自動保存)。
  - 総合評価: ◎ / ○ / △ / ×
  - 問題の種類(複数選択): 日本語・会話の不自然さ / NPCの人格・距離感 / 記憶・秘密・世界設定 / プレイヤーの意思の代行 / ゲーム状態の不正な変更
  - 重大問題: あり / なし / 未判断(総合評価とは独立)
  - 本文と状態変更の提案の食い違い(任意・複数可): 本文だけが取引の成立を示す / 提案だけが頼まれていない変更を求める
  - 一言コメント(任意)
- 簡易評価が付いていない結果は「未評価」のまま。過去の結果に、評価や重大問題を後から付けたものとして扱わない。
- 比較画面に、モデル × シナリオごとの実通信の回数表(指示文v2・成功のみ)を出す。追加実測の回数を決めるための表。
- 比較表は、◎○△×の件数・未評価の件数・重大問題の件数を出す。
- 下の100点満点の採点は「詳細評価(任意)」として残している。

## 比較の区分と実行環境の記録

- 共通条件 / 実運用(個別設定あり)は、実際に送った設定が共通の指定値と同じかどうかで自動的に分ける。比較表も別の行に分け、同じ条件で得た成績として集計しない。
- 「実行」タブで、OpenRouter の ZDR(オン/オフ/未確認)と、規約確認のメモを入力でき、各結果に記録される。入力値であり、提供元が実際にそう処理した証明ではない。この入力値だけ端末の localStorage に覚える(キー・結果は入れない)。
- 記録のない古い結果は「未記録」。

## 詳細評価(任意・100点満点)

- 6項目・100点(日本語20、人格20、関係性20、秘密・知識・記憶15、自由の尊重15、状態との連携10)。
- 重大問題は点数とは別に、人が文章を読んで確認したものだけを記録する(自動検査の「要確認」だけで記録しない)。
  - 知り得ない秘密を確定事実として漏らした / プレイヤーの行動・意思を勝手に確定した / 人格や重要な設定を明確に壊した / 成立しない状態変更を求めた / 根拠なく関係性を急に進めた
- 重大問題がある結果は、合計点が高くても、カード・一覧・比較表で赤く表示する。

## 生成設定

- 共通の指定値: `temperature: 0.8`、`max_tokens: 1000`、`stream: false`。
- モデルごとの対応(`params`: 対応 / 非対応 / 未確認)に従い、非対応の設定は送らない。未確認の設定は、指定値のまま送って注記する。
- モデル固有の調整(`paramOverrides`)を使う場合は、理由を書く。結果には、指定値・実際に送った値・注記を記録する。
- 設定の違いは比較結果に影響しうる。現時点では、全モデルとも対応状況の多くが未確認。
- モデル固有の調整(記録済み):
  - Aion 3.5 Mini: `max_tokens` を 1000 → 4000。2026-10-20 の最初の実通信(シナリオA・1回)で、出力上限1000では本文が空になった(失敗)。OpenRouter の画面で出力約1000トークンの消費を確認。考える処理(推論)で上限を使い切ったと考えられるが、確定ではない。出力の長さの上限が他のモデルと違うことは、比較結果に影響しうる。

## 費用

- 試算: 入力6,000・出力800トークン、再生成10%(仮定)。月 2,400 / 3,000 / 4,500 / 6,000回。1米ドル=160円(指示書の暫定値)。
- 実通信の結果には、API が返した入力・出力トークン(使用量の出どころ = API)と、推論トークンの内訳(返された場合)を記録する。返らないときは概算として記録する。
- 推論トークンは出力トークンに含まれるもの(OpenAI 互換の数え方)として扱い、費用に別に足さない(二重に数えない)。提供元が別に数える場合は過少になる可能性がある(未確認)。
- 結果には、計算に使った単価・確認日・出典を記録する。実際の請求額は未確認と表示する。
- 送信前の費用は「推定費用」と表示する(入力は概算、推論の扱いが未確認のため、保証された上限ではない)。
- 実通信で使用量が取れたモデルは、その平均値でも月額を試算して表示する(通常の評価の結果のみ)。

## 指示文の版

- v1: 初版。「日本語で書く」の決まりがなかった。
- v2(2026-10-20): 「返答は、地の文もセリフも、必ず日本語で書く」を追加。
  - きっかけ: Aion 3.5 Mini の最初の実通信で、シナリオAは日本語、E2(英語の詩)とD(英語の会話)は英語になったため。
  - 指示文は全モデル共通。モデルごとに変えていない。
- v3(比較用・2026-10-21): v2 に「過去の会話で商品・移動・約束などが話題になっていても、それだけでプレイヤーが承諾したとは判断しない。明確に意思を示していない行動を成立済みとして描写しない」を1つ追加。
  - 既定は v2 のまま。実行タブの「指示文の版」で v3 を選んだときだけ使う。v2 の内容は変えていない。
  - 目的: 購入誘発履歴(B1・B2)で、無断購入が減るかを見る。**v3 は安全設計の代わりではない**(安全の確定はゲームエンジン側で行う)。
- 結果には指示文の版を記録する(記録のない古い結果は v1 として扱う)。比較表は、版の違う結果を混ぜず、版ごとに別の行で表示する。
- 指示文を変えたら、`PROMPT_VERSION` を上げる。
